# Task: S3 storage layer (SeaweedFS), for CloudNativePG backups

Read CLAUDE.md first and follow its rules. Explain each file in plain words BEFORE
you create it (what it is, why, what it depends on). No network analogies; the user
wants plain, detailed explanations. Never print secrets. Ask before anything destructive.

## Why
CloudNativePG (next stage) archives base backups and WAL (transaction logs) to an S3
bucket via the Barman Cloud plugin. Point-in-time recovery needs that bucket. We run a
small S3-compatible service inside the cluster: SeaweedFS, one pod.

## Design (decided, do not change without asking)
- New namespace `storage`. New Flux layer: folder `infrastructure/storage/`, Flux
  Kustomization `infra-storage` in `clusters/demo/infrastructure.yaml`, with
  `dependsOn: infra-configs`, `wait: true`, and the same `decryption: sops / sops-age`
  block as infra-configs.
- Objects in `infrastructure/storage/`:
  1. `namespace.yaml` (namespace `storage`)
  2. `seaweedfs-s3-config.sops.yaml`: Secret `seaweedfs-s3-config` in `storage`,
     key `s3.json` = SeaweedFS identities file (see format below), SOPS-encrypted.
  3. `seaweedfs.yaml`: PVC (5Gi, default storage class `standard`/local-path),
     Deployment (replicas 1, strategy Recreate), Service `seaweedfs` port 8333 (ClusterIP).
     Mount the Secret read-only at /etc/seaweedfs and the PVC at /data.
  4. `create-bucket-job.yaml`: Job that creates bucket `pg-backups` and exits 0 if it
     already exists (idempotent). It must wait until the S3 endpoint answers.
  5. `kustomization.yaml` listing the above.
- Credentials for PostgreSQL: Secret `s3-credentials` with keys `ACCESS_KEY_ID` and
  `ACCESS_SECRET_KEY` in namespace `databases` (create `infrastructure/storage/databases-namespace.yaml`
  too, since CloudNativePG will live there). SOPS-encrypted file
  `s3-credentials.sops.yaml`. Same access/secret key pair as in s3.json.
- Credentials are random, generated by a script `scripts/s3-secrets.sh` (like
  scripts/sops-demo.sh): openssl rand, write both Secret files, `sops --encrypt --in-place`,
  never echo the values. Idempotent: refuse to overwrite existing files unless `--force`.
- Plain HTTP inside the cluster for now (traffic never leaves the cluster). Write a short
  ADR `docs/adr/0002-in-cluster-s3.md` (problem, options SeaweedFS vs MinIO vs cloud S3,
  choice, trade-off: single replica, no TLS in-cluster, data lost with the cluster PV).
  Also write the ADR for pinned chart versions `docs/adr/0001-pinned-versions.md`.

## SeaweedFS identities file format (from the SeaweedFS S3 credentials wiki)
{"identities":[{"name":"backup","credentials":[{"accessKey":"...","secretKey":"..."}],
"actions":["Admin","Read","Write"]}]}
S3 endpoint port is 8333 in the SeaweedFS docs.
